# HireGameDev — Architecture & Scope Decisions (`DECISIONS.md`)

Primary living architecture docs, ADRs, and milestone roadmap live in **Notion (`HireGameDev (v2.0)`)**.
Per Build Blueprint v2.0 (Section 1, Rule 5), every intentional deviation or key choice from the blueprint is logged in one line below.

## Baseline Principles (from Blueprint v2.0 Section 13.F)
- **Hard filters before scoring:** Dealbreakers (work mode, engine gate, salary ceiling, notice period, availability) exclude pairs instead of hiding inside a percentage.
- **Evidence factor in skill score:** Backed (`0.90`) and verified (`1.00`) skills outweigh bare claims (`0.70`), preventing keyword stuffing.
- **Years-derived seniority:** Matching uses `years_experience`, not self-declared seniority labels.
- **Current CTC hidden by default:** Studios see `expected_ctc_lpa`; `current_ctc_lpa` stays hidden unless candidate opts in.
- **Contact details gated & no cold messages:** Phone and email release only at `shortlisted` or accepted invite.
- **Free launch first, access billing later:** Launch free through Phase 4; charge for access/capacity in Phase 6 after marketplace gates are met.
- **No free-tier AI for resumes:** PII is redacted before LLM calls, paid no-training tier only, and raw resume text is never persisted.

## Accepted Decisions & Blueprint Deviations
- **2026-10-23 (`ADR-001`):** Adopt exact C# / ASP.NET Core 8 + EF Core (`Npgsql`) + PostgreSQL 16 + SignalR + Hangfire + custom Neon Yellow & Obsidian CSS token stack.
- **2026-10-23 (`ADR-002` — Deviation from 3-project layout):** Split `HireGameDev.Core` into zero-dependency `HireGameDev.Domain` and EF-free `HireGameDev.Application` (4 projects: `Domain`, `Application`, `Infrastructure`, `Web`; no MediatR, no AutoMapper, no Generic Repository).
- **2026-10-23 (`ADR-003` — Deviation from Razor Pages):** Use **ASP.NET Core MVC** (`Controllers/`, `Views/`, `Models/`) instead of Razor Pages; controllers stay strictly thin and delegate all logic to `Application` handlers.
- **2026-10-23 (`ADR-004`):** Generate all EF Core migrations locally via `dotnet ef` (never hand-forge `ModelSnapshot.cs`), and store all enums as `snake_case` `text` via `HasConversion<string>()` with PostgreSQL `CHECK` constraints.
- **2026-10-23 (`ADR-005` — Deviation on test projects):** Start with zero test projects (`T1`) during Foundation/CRUD modules to keep velocity high and avoid mock/Docker friction; revisit pure math tests when building `MatchingEngine` in Phase 3.
- **2026-10-24 (`M0.2`):** Keep standard `IdentityUser<Guid>` columns intact on `users` for full `UserManager` store compatibility while storing real candidate phone numbers strictly on `candidate_profiles.phone` in Phase 1.
- **2026-10-24 (`ADR-006` — Auth & SSO UX):** Never email plaintext temporary passwords; SSO-only accounts (`password_hash == null`) use signed Set-Password links + smart Login prompts. First-time signups pick Candidate vs. Studio upfront (`Complete Account` step for SSO); GitHub Sign-In is restricted to Candidates only (wired via first-party ASP.NET Core 8 `AddOAuth` + `/user/emails` verified-email lookup with zero third-party OAuth packages), while Google Sign-In is offered to both Candidates and Studios.
- **2026-10-24 (`ADR-007` — Pluggable Email API):** Route all transactional emails through provider-agnostic `IEmailSender` (`Email:Provider = "Dev" | "Resend"`), using `DevEmailSender` (console + `logs/emails/*.html` previews) locally and `ResendEmailSender` (`HttpClient`) in production so switching email providers requires zero Application/Web changes.
- **2026-10-24 (`ADR-008` — Deviation on Studio personal emails):** Allow any valid email (including Gmail/Outlook) at Studio registration; require complete Studio profile before verification submission; company-domain studios follow standard verification while personal-email indie studios can submit for manual Admin review (`pending`), unlocking job publishing only after Admin approval (`verified`).
- **2026-11-04 (`ADR-009` — Enriched Reference Taxonomy & Seeding):** Enrich `cities` (`slug`, ISO `state_code`, `aliases[]`, `metro_group`, 10 Indian gaming hubs), `skills` (`subcategory`, self-FK `parent_skill_id`), and `skill_relations` (directional `relation_type`: `implies`, `superset`, `peer_tool`, `transferable` calibrated to Phase 3 `F2 >= 0.80` Engine Gate), seeded from validated slug-keyed JSON manifests with Admin CSV import/export support.
- **2026-11-04 (`ADR-010` — Settings, Audit, DPDP Consent & Trusted-Proxy Rate Limiting):** Unify `app_settings` (60s cached JSONB), `audit_logs` (PostgreSQL `inet` IP + DB/service-enforced mandatory `reason` for `actor_type = 'admin'`), and append-only versioned `consent_records` (`legal.terms_version` / `legal.privacy_version` seeded at `"1.0"`) into one `M0_5_SettingsAuditConsent` migration, paired with loopback/trusted-proxy `ForwardedHeaders` and HTTP `429` `AddRateLimiter` policies on auth endpoints.
- **2026-11-05 (`ADR-011` — Design System, Layout & WCAG Contrast Calibration):** Adopt Linear/Hitmarker-inspired Neon Yellow + Obsidian token architecture with self-hosted `Inter` + `Space Grotesk` (`latin` + `latin-ext` `.woff2` for `₹`), replaceable geometric `HGD` SVG wordmark/favicon, `System` default theme synced to `hgd-theme` cookie + `users.theme_preference`, minimal geometric cards (no stock/gamer clutter), day-one 4-tab mobile bottom nav for signed-in Candidates, and WCAG 2.1 AA/AAA calibrated tokens (`--*-ink` >= `5.18:1` on badges, `--on-danger` >= `5.77:1`, `--control-border` >= `3.23:1`, and `--disabled-*` >= `4.61:1` with dashed inactive borders) across both Light and Dark themes (`M0.6a`–`M0.6c`).
- **2026-11-05 (`ADR-012` — Three-Domain Architecture & Single-Email Dual-Role Identity):** Split product surfaces across `hiregamedev.com` (landing, `/Legal/*`, `/Admin`), `jobs.hiregamedev.com` (public job board, Candidate portal, public studio profiles at `/studios/{slug}`), and `studio.hiregamedev.com` (Studio hiring & verification portal) within a single modular ASP.NET Core 8 host (`Portals:DeploymentMode` ready for future per-portal deployments). Enforce portal-tailored `A1` auth (`jobs.` = Google + GitHub + Email; `studio.` = Google + Email with GitHub disabled), support both `candidate` and `studio` roles on a single verified email via `user_roles` without duplicate accounts, share `.hiregamedev.com` `SameSite=Lax` cookies (`hgd.auth`, `hgd.csrf`, `hgd-theme`, `hgd-cookies`) with file-persisted Data Protection keys, and enforce strict `AllowedHosts` + allowlisted cross-subdomain redirect validation.
- **2026-11-05 (`ADR-013` — Phase 1 Scope, Proofs & Adapter Strategy):** Generate incremental per-module EF Core migrations across Phase 1 (`M1.1a`, `M1.2a`, `M1.3a`, `M1.4a`, `M1.8a`, `M1.9a`, `M1.11c`); make GSTIN optional under `ADR-008` so Indian indie studios can verify via live game-store page / domain / MCA-UDYAM proof in the Admin review queue (`24–48h` target SLA); ship `candidate_studio_blocks` (hide profile from chosen studios) and the Fresher education `+15` completeness rule in Phase 1; and wire pluggable `ISmsSender` and `IResumeLlmClient` with local `Dev` adapters first before selecting live SMS/LLM vendors pre-launch.
- **2026-11-06 (`ADR-014` — Relational `portfolio_link_skills`, NDA Studio Masking, Proof Integrity & Centralized Completeness):** Replace `portfolio_links.skill_ids int[]` with a relational `portfolio_link_skills (portfolio_link_id, skill_id)` join table for FK referential integrity in `M1.5` `IEvidenceService` and admin skill merges; add `shipped_titles.hide_studio_in_public` alongside `is_nda` so confidential studio and project info can be redacted on public/studio projections while retaining internal owner records; enforce strictly backend-controlled `verification` (resetting to `none` if credit-identity fields change) and clear UI separation between submitted proof (`Backed`) and verified proof (`Verified`); validate/normalize external URLs strictly as public `https://` (`ExternalUrlRules`); and centralize completeness calculation behind `ICandidateCompletenessCalculator`.
- **2026-11-06 (`ADR-015` — Token-Aware `IEvidenceService`, Pluggable `IVerifiedSkillEvidenceProvider` & Targeted Unit Tests):** Recompute `candidate_skills.evidence_level` (`Claimed = 0`, `Backed = 1`, `Verified = 2`) idempotently within the active `DbContext` transaction on Step 2/3/4 saves using a dedicated zero-regex token scanner (`SkillEvidenceTextMatcher` handling `C`, `C#`, `C++`, `Go`, `.NET` boundaries without false positives), keeping NDA shipped titles eligible for internal evidence, introducing `IVerifiedSkillEvidenceProvider` so future Phase 7 skill challenges never downgrade on profile saves, surfacing explicit labels (`Self-declared`, `Supporting evidence submitted`, `Independently verified`), and introducing `tests/HireGameDev.UnitTests` (`xUnit` + EF Core `InMemory`, updating `ADR-005` for pure-rule & service invariants).
- **2026-10-23 (`ADR-016` — Provider-Independent `IFileStorageService`, Decoupled Image Processing & Cloudflare R2 Readiness):** Separate image validation/transformation (`IImageProcessor` via `SixLabors.ImageSharp` enforcing 1 MB max, JPEG/PNG/WebP magic-byte verification, `<= 4096x4096` header guard, `AutoOrient`, EXIF/IPTC/XMP/CICP metadata stripping, and `.webp` encoding) from object storage (`IFileStorageService` with explicit `StorageVisibility.Private` vs `StorageVisibility.Public` and config-switched `Storage:Provider = "Local" | "CloudflareR2"`). Persist only normalized S3-compatible relative object keys (`avatars/<guid>.webp`, `logos/<guid>.webp`) in PostgreSQL, implement `LocalFileStorageService` outside `wwwroot` now with atomic temp-file writes and path-containment guards, and serve private candidate photos strictly through authorized app endpoints (`/Media/Candidates/{id}/Avatar`).
